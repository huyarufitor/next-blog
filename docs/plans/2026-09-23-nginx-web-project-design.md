# 从前端静态资源到后端 API：一份可维护的 Nginx 配置

## 已确认的设计

**目标：** 面向需要同时部署前端和后端的全栈开发者，解释 Nginx 在一个 Web 项目中的职责，并提供一份可复制、可排错的生产基础配置。

**场景：** 前端构建产物位于 `/var/www/example.com/dist`，后端监听 `127.0.0.1:3000`，Nginx 对外提供 `80/443`，将 `/api/` 转发到后端。

**范围：** 静态文件、SPA 路由回退、反向代理、HTTPS 跳转、代理请求头、资源缓存、上传大小、超时、WebSocket/流式响应、验证与常见故障排查。

**不展开：** Nginx 安装、云平台负载均衡、Kubernetes、多机集群、WAF 和证书申请全流程。

## 文章结构

1. 解释浏览器、Nginx、静态文件和后端 API 的请求链路。
2. 约定目录、域名和端口，避免路径与端口混淆。
3. 从最小配置开始，分别配置页面和 `/api/`。
4. 解释 `try_files`、`location` 匹配和 `proxy_pass` 路径行为。
5. 补齐 HTTPS、真实 IP、静态缓存、请求体大小和超时。
6. 说明 WebSocket、SSE 等长连接场景需要调整的配置。
7. 给出完整配置和 `nginx -t`、reload、curl 验证流程。
8. 用现象、原因、检查方式整理 404、502、413、跨域和流式响应问题。

## 内容与安全约束

- 只使用 `example.com`、`127.0.0.1:3000` 等示例值。
- 不放入真实域名、服务器地址、证书路径、密码或 Token。
- 明确指出示例配置需要结合项目、证书和后端框架实际调整。
