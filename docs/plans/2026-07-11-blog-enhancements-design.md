# 博客中文化与增强设计

日期：2026-07-11

## 目标

在现有 Next.js 16、React 19、TypeScript、Tailwind CSS 4 与本地 MDX 架构上，完成全站中文化，并补齐文章封面、动态 OG 图、暗色模式、隐私友好的访问统计和 Vercel 部署能力。

## 站点身份与内容

站点采用 AI Mock 品牌「栈间笔记」，作者为「林默」，身份明确标注为 AI 技术写作者，避免把虚构资料表述为真实个人身份。站点介绍、导航、页面标题、空状态、搜索提示、日期和阅读时长全部使用中文。

站点 URL 从 `NEXT_PUBLIC_SITE_URL` 读取，本地默认使用 `http://localhost:3000`。生产部署成功后，在 Vercel 环境变量中写入实际生产域名。Giscus 仓库与分类信息继续使用公开环境变量；配置不完整时不加载评论组件，而是显示中文配置提示。

## 文章封面与分享图

为两篇示例文章生成与主题对应的原创位图封面，存放在 `public/images/posts`，并通过 MDX frontmatter 的 `cover` 字段关联。文章卡片和正文页使用 `next/image` 输出稳定尺寸的响应式图片。

站点级和文章级 OG 图使用 Next.js `ImageResponse` 动态生成。文章 OG 图包含站点名称、文章标题、摘要和主题标签，并复用文章视觉配色；即使封面缺失，也能生成可用的分享图。

## 暗色模式

使用 `next-themes` 管理浅色、深色和跟随系统三种状态。主题选择保存在浏览器中，并在首次渲染时避免主题闪烁。导航栏提供图标按钮与可访问标签，Giscus 主题随站点主题同步。

全局颜色改为语义 CSS 变量，浅色和深色分别定义背景、正文、弱化文字、面板、边框和强调色。现有布局结构不变，避免为主题功能引入页面级重构。

## 统计与部署

接入官方 `@vercel/analytics`，由 Vercel 在生产环境处理页面访问统计，不添加自定义用户标识或额外个人数据采集。开发环境保留组件但不产生生产统计数据。

部署使用 Vercel CLI。完成 lint 和 production build 后创建或关联 Vercel 项目并执行生产部署。若本机尚未登录 Vercel，部署流程停在官方授权步骤，并明确报告该外部账号阻塞；只有获得可访问的生产 URL 才判定部署完成。

## 错误处理与验证

- Giscus 环境变量缺失时显示中文提示，不向无效仓库发起请求。
- `NEXT_PUBLIC_SITE_URL` 缺失时使用本地 URL，确保构建和元数据生成不失败。
- 封面缺失时卡片和文章页保持稳定布局，OG 图仍可生成。
- 运行 ESLint 和 Next.js production build。
- 启动开发服务器，检查首页、文章页、搜索页、标签页，以及浅色和深色桌面/移动端视图。
- 验证 OG 图片路由返回图片，Vercel Analytics 正确注入页面。
